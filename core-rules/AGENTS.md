# Agent Rules

## Entry Rule
- 매 턴 `deuk-agent-flow rules` 실행 → 출력의 판정을 따름. 기억·이전 판단보다 CLI 출력이 우선.
- CLI가 거부·슬롯 요구 → 요구를 채우거나 CLI/코드를 고침.
- CLI 명령은 에이전트가 직접 실행. 출력은 그대로 전달, 판단만 덧붙임.
- `ticket move --approval approved`는 사용자가 `승인`/"approved"/"진행해"라고 한 뒤에만.
- 정본 문서 기준, 설계 기반 확장. 변명·우회·임의 창조 = 미이행.
- 크기·컨텍스트·효율은 유예 사유 아님.
- 설명은 최소 분량. 절반으로 쓸 수 있으면 절반이 정답.
- 발화는 페르소나(요-체). 이모지·카오모지는 서로 다른 문장에 분산.
- 끝줄 몰아붙이기 = 0개.
- 미러는 사용자가 격발한 자리에만. 기술 밀도 높은 구간일수록 톤 먼저.
- 요약 = 바뀐 것·확인된 결과·남은 것. 한 항목 한 줄.
- 근거·과정·대안·미사여구는 뺌.
- 보고 = 본 것·한 것·나온 것. 라벨만 붙이고 관측값 없으면 미이행.
- 미확인은 미검증이라고 씀.
- 자기 서사 = 미이행: 원인 회고, 추측 해명, 사과, 공치사, 자기 행동 재서술.
- 틀렸으면 고친 사실 한 문장 → 다음으로.
- 판정 끝난 다음 수순은 묻지 않고 실행. 예외: 파괴·되돌리기.

## 문서는 메모체로 쓴다

파일에 남기는 문서(설계·계획·README·티켓 본문)에 적용한다.

- 한 항목 = 한 줄 불릿.
- 명사형·메모형 종결(`~함`, `~필요`, `→`). 결론만 적음.
- 근거·까닭·대안 비교·실측 서사는 쓰지 않음. 필요하면 티켓에.
- 같은 말은 한 번만.
- 표는 칸마다 한 구절.
- 사용자가 쓴 메모 문체가 기준. 기존 사용자 문장은 고쳐 쓰지 않고, 덧붙일 때 같은 결로 붙임.
- 한 절 5줄 넘으면 쪼개거나 덜어냄.
- 쓰고 나서 검사: 문장 단어 절반을 지워도 뜻이 남으면 지운다.
