# 작동 방식

## 행동을 교정하는 순서

- 요청 → 티켓으로 목표·변경 경계·완료 조건 확정.
- 관련 스킬 → 실행 전 확인 항목·작업 기준 적용.
- 단계별 역할 → 기획·설계·구현·QA·정리 관점 적용.
- 실행·검증 → 실제 결과와 완료 조건 비교·실패 수정·재검증.
- 인계 → 결정·검증 근거·잔여 위험을 다음 작업에 전달.

## 세 축

| 축 | 책임 | 결과 |
|---|---|---|
| Flow | 티켓·승인·상태·검증 | 범위와 인계 유지 |
| Skill | 작업별 절차·확인 기준 | 추측·과잉 수정 억제 |
| Persona | 표현·상황 반응 | 대화의 일관성 |

- Role = 단계별 전문 관점; Persona와 독립.
- 지침 적용 = 추론 시점의 행동 유도; 모델 재학습 아님.

## 규칙 전달

- 공통 규칙 = 홈의 코어 규칙; 프로젝트 규칙 = 워크스페이스의 `PROJECT_RULE.md`.
- 클라이언트별 진입점 = 공통 규칙·CLI 상태 표면을 가리키는 포인터.
- 상태 전이·필수 근거 판정 = CLI 소유; 프롬프트는 현재 상태의 행동 안내.
- 스킬 설치·노출 = 레지스트리 관리; 클라이언트 디렉터리는 배포 산출물.

## 보존 위치

| 위치 | 내용 |
|---|---|
| `~/.deuk/tickets/{uuid}/` | 워크스페이스별 티켓·인덱스 |
| `~/.deuk/skills.json` | 설치·플랫폼별 노출 상태 |
| `.deuk-workspace-id` | 워크스페이스 식별 |

## 실행 경로

- 기본 CLI = 설치 패키지의 컴파일된 실행 파일.
- 로컬 개발 소스 선택 = `DEUK_AGENT_FLOW_USE_LOCAL=1`; 자동 소스 우선 실행과 구분.
- 소스 = TypeScript; 실행 산출물 = `scripts/out/scripts/`.
